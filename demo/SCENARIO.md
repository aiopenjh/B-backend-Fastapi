# 발표 시연 순서 (상태 코드 보여 주기 포함)

시연 앱으로 켜고(`demo/README.md`), 화면 오른쪽 **서버 로그 창**에서 상태 번호를 같이 보여 줍니다.
번호 색: 200 초록 · 3xx 파랑 · 4xx 주황 · 5xx 빨강.

- 주소: `http://127.0.0.1:8000` (화면), `http://127.0.0.1:8000/docs` (API)
- 계정: 관리자 `test@test.org`, 운영자 `owner.a@example.com` · `owner.b@example.com`, 손님 `customer.a@example.com` · `customer.b@example.com`
- 비밀번호: `src/seed.py`의 `ADMIN_PASSWORD`(관리자), `SEED_PASSWORD`(나머지 시드 계정)
- 시연 앱에서는 마감·인원 초과 시간 버튼도 눌리게 열려 있습니다 (누르면 서버가 409로 막는 걸 보여 주려고).
- 순서는 `demo/README.md`의 "시연 데이터 채우기"를 한 번 해 둔 뒤 기준입니다.
- **시연 계정 바꾸기:** 관리자로 로그인하면 로그 창 위에 [관리자] [운영자A] [운영자B] [고객A] [고객B] 버튼이 생깁니다. 누르면 그 시드 계정으로 진짜 로그인한 상태가 되어 403·404·409가 실제와 똑같이 나옵니다. 아래 순서의 "로그아웃 → ○○로 로그인"은 이 버튼으로 바꿔도 됩니다. 로그아웃하면 버튼이 사라집니다 (시연 앱에서만).

## 1. 시작과 로그인

| 순서 | 하는 일 | 화면 | 로그 창 |
| --- | --- | --- | --- |
| 1 | 주소창에 `127.0.0.1:8000` | 식당 둘러보기로 이동 | `GET / 307` → `GET /ui/restaurants 200` |
| 2 | 아래 탭 "로그인" → 틀린 비밀번호로 로그인 | "이메일 또는 비밀번호가 올바르지 않습니다." | `POST /ui/login 401`, `화면 로그인 실패 401` |
| 3 | 관리자로 다시 로그인 | 운영자 목록, 위에 "관리자로 로그인 중" | `POST /ui/login 303` → `200` |

## 2. 관리자 (전체 보기)

| 순서 | 하는 일 | 화면 | 로그 창 |
| --- | --- | --- | --- |
| 4 | 운영자A "식당 보기" → 식당 "예약 보기" | 날짜별 예약 + 예약자 이름·연락처 | `200` |
| 5 | 아래 탭 "로그아웃" | 로그인 화면 | `POST /ui/logout 303` |

## 3. 손님 (권한 막힘 → 둘러보기 → 예약)

| 순서 | 하는 일 | 화면 | 로그 창 |
| --- | --- | --- | --- |
| 6 | 손님A로 로그인 | 식당 둘러보기 | `303` → `200` |
| 7 | 주소창에 `127.0.0.1:8000/ui/admin/owners` | "관리자만 볼 수 있어요" | **`403`**, `화면 안내 403` |
| 8 | 주소창에 `127.0.0.1:8000/ui/owner/restaurants` | "운영자만 볼 수 있어요" | **`403`** |
| 9 | 주소창에 `127.0.0.1:8000/ui/restaurants/999999` | "식당을 찾을 수 없어요" | **`404`** |
| 10 | 지역(구)·상세 지역(동)·음식 종류로 찾기 → 식당 이름 누르기 | 메뉴 + 날짜·인원별 시간 | `200` |
| 11 | 날짜·인원·시간 고르고 "예약하기" | "예약됐어요" + 예약 번호 | `POST .../reserve 303` → `200` |
| 12 | 같은 시간을 한 번 더 예약 | "이미 예약한 시간이에요." | **`화면 예약하기 실패 409 DUPLICATE_RESERVATION`** |
| 13 | 인원을 늘려 "최대 N명"으로 표시된 시간을 골라 예약 | "한 번에 예약할 수 있는 인원을 넘었어요." | **`409 PARTY_SIZE_EXCEEDED`** |
| 14 | 아래 탭 "내 예약" → 방금 예약 "취소" | "예약 #N을 취소했어요" | `POST /ui/reservations/N/cancel 303` |
| 15 | 다른 예약을 하나 더 해 둠 (운영자 취소용) | "예약됐어요" | `303` |

마감(자리 없음) 409를 보여 주려면, 시연 직전에 한 시간을 꽉 채워 둡니다:

```bash
uv run python demo/make_full.py "동네백반"
```

출력에 나온 날짜로 그 식당 상세를 열면 그 시간이 "마감"으로 보입니다 (시연 앱이라 눌림). 고객A로 누르면 **`409 SLOT_SOLD_OUT`**("방금 자리가 찼어요")이 나옵니다. 시연용 손님 여러 명이 예약해서 채우기 때문에 좌석 수와 예약 합이 정확히 맞습니다.

## 4. 운영자 (내 식당 확인·취소)

| 순서 | 하는 일 | 화면 | 로그 창 |
| --- | --- | --- | --- |
| 16 | 로그아웃 → 운영자A로 로그인 | 운영 식당 | `303` → `200` |
| 17 | 15번에서 예약한 식당 "예약 확인하기" | 손님A 예약이 보임 | `200` |
| 18 | 그 예약 "취소" | "예약 #N을 취소했어요", 상태 "취소" | `303` |
| 19 | 같은 예약을 다시 취소 (다른 탭에서 열어 둔 경우 등) | "이미 취소된 예약이에요." | **`화면 예약 취소 실패 409 ALREADY_CANCELLED`** |
| 20 | 운영자B 식당의 예약 주소(`/ui/owner/restaurants/{운영자B 식당 번호}/reservations`) | "예약을 볼 수 없어요" | **`403`** |
| 21 | 주소창에 손님 화면 `127.0.0.1:8000/ui/restaurants` (운영자로) | 손님 화면 대신 운영 식당으로 돌려보냄 | `303` (운영자는 손님 공간에 들어가지 않음) |

## 5. API로 보여 주기 (`/docs`)

| 순서 | 하는 일 | 결과 |
| --- | --- | --- |
| 22 | 로그인 없이 `GET /api/v1/users/me/reservations` | **401** |
| 23 | `POST /api/v1/auth/login` → Authorize → `GET /users/me/reservations` | 200 |
| 24 | `POST /api/v1/auth/logout` → 같은 토큰으로 다시 `GET` | 204 → **401** (로그아웃한 토큰 차단) |
| 25 | `POST /api/v1/reservations`에 `party_size: 0` | **422** (입력 형식 오류) |
| 26 | `POST /api/v1/users`로 새 손님 가입 | 201 |
| 27 | 손님 토큰으로 `GET /api/v1/owner/restaurants` | **403** (운영자만) |
| 28 | `GET /api/v1/restaurants/999999` | **404** `RESTAURANT_NOT_FOUND` |

## 상태 코드 한눈에

| 코드 | 뜻 | 시연에서 내는 법 |
| --- | --- | --- |
| 200 | 성공 | 화면 열기 |
| 303 | 처리 뒤 다른 화면으로 (로그인·예약·취소 뒤) | 로그인, 예약하기, 취소 |
| 307 | 주소 옮김 | `127.0.0.1:8000` |
| 401 | 누군지 모름 (로그인 안 함·비밀번호 틀림·로그아웃한 토큰) | 2, 22, 24 |
| 403 | 누군지는 알지만 권한 없음 | 7, 8, 20, 27 |
| 404 | 없음 (또는 남의 것이라 숨김) | 9, 28 |
| 409 | 지금 상태와 부딪힘 (중복·인원 초과·마감·이미 취소) | 12, 13, 19, 마감(`make_full.py`) |
| 422 | 입력 형식이 틀림 | 25 (화면: 주소에 `?party_size=0`) |
| 500 | 서버 오류 | 시연에서는 나오지 않아야 함 |
