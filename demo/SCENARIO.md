# 발표 시연 순서 (상태 코드 보여 주기 포함)

[시연 앱을 켜고](README.md), 화면 오른쪽 **서버 로그 창**에서 상태 번호를 같이 보여 줍니다.
번호 색: 200 초록 · 3xx 파랑 · 4xx 주황 · 5xx 빨강.

- 주소: `http://127.0.0.1:8000` (화면), `http://127.0.0.1:8000/docs` (API)
- 계정: 관리자 `test@test.org`, 운영자 `owner.a@example.com` · `owner.b@example.com`, 손님 `customer.a@example.com` · `customer.b@example.com`
- 비밀번호: `src/seed.py`의 `ADMIN_PASSWORD`(관리자), `SEED_PASSWORD`(나머지 시드 계정)
- 시연 앱에서는 마감·인원 초과 시간 버튼도 눌리게 열려 있습니다 (누르면 서버가 409로 막는 걸 보여 주려고).
- 순서는 `demo/README.md`의 "시연 데이터 채우기"를 한 번 해 둔 뒤 기준입니다.
- **노쇼 버튼이 나오는 시점**은 `.env`의 `NO_SHOW_GRACE_SECONDS`(초)입니다. 기본 900(15분), 평소 300(5분), **시연 때는 60(1분)** 을 넣으면 1분만 기다려도 "노쇼" 버튼을 보여 줄 수 있습니다. 자동 노쇼(시간 지나면 서버가 알아서 취소)는 쓰지 않습니다 — `NO_SHOW_CHECK_SECONDS`는 넣지 않습니다.
- **시연 계정 바꾸기:** 로그 창 맨 위에 [관리자] [운영자A] [운영자B] [고객A] [고객B] 버튼이 로그인한 뒤에는 항상 고정돼 있습니다 (로그아웃하면 숨김). 누르면 그 시드 계정으로 진짜 로그인한 상태가 되어 403·404·409가 실제와 똑같이 나옵니다. 아래 순서의 "로그아웃 → ○○로 로그인"은 이 버튼으로 바꿔도 됩니다 (시연 앱에서만).

| 순서 | 하는 일 | 화면 | 로그 창 |

## 3. 손님 (권한 막힘 → 둘러보기 → 예약)

| 순서 | 하는 일 | 화면 | 로그 창 |
| --- | --- | --- | --- |
| 6 | 손님A로 로그인 | 식당 둘러보기 | `303` → `200` |
| 7 | 주소창에 `127.0.0.1:8000/ui/admin/owners` | "관리자만 볼 수 있어요" | **`403`**, `화면 안내 403` |
| 8 | 주소창에 `127.0.0.1:8000/ui/owner/restaurants` | "운영자만 볼 수 있어요" | **`403`** |
| 9 | 주소창에 `127.0.0.1:8000/ui/restaurants/999999` | "식당을 찾을 수 없어요" | **`404`** |
| 10 | 지역(구)·상세 지역(동)·음식 종류로 찾기 → 식당 이름 누르기 | 메뉴 + 날짜·인원별 시간 | `200` |
| 11 | 잔여 10석·한 팀 최대 4명 이상인 시간을 골라 4명 예약 | 완료 안내와 시간 버튼에 **남은 6석** | `POST .../reserve 303` → `200` |
| 12 | 같은 시간을 한 번 더 예약 | "이미 예약한 시간이에요." | **`화면 예약하기 실패 409 DUPLICATE_RESERVATION`** |
| 13 | 이미 예약한 시간과 다른 열린 시간에서 한 팀 최대 인원을 넘겨 예약 | "한 번에 예약할 수 있는 인원을 넘었어요." | **`409 PARTY_SIZE_EXCEEDED`** |
| 14 | 아래 탭 "내 예약" → 방금 예약 "취소" | "예약 #N을 취소했어요" | `POST /ui/reservations/N/cancel 303` |
| 15 | 운영자A 소유 식당에 예약 하나를 더 접수 (운영자 취소용) | "예약됐어요" | `303` |

관리자 첫 화면을 별도 브라우저 세션에서 열고 검색어를 비워 둡니다. 11번 예약 후 관리자 창을 보면 3초 주기로 식당 표가 갱신되고 방금 예약한 식당이 맨 위에 표시됩니다.

식당 상세의 기본 날짜는 접속일 기준 내일입니다. **11월 10일에 넣은 기본 시드로 11월 11일에 발표한다면 날짜를 11월 11일로 직접 변경**합니다. 한옥집 기본 시드는 시드를 넣은 다음 날 18시 잔여 8석, 19시 잔여 2석, 20시 잔여 0석으로 시작합니다. 시연 중 예약·취소하면 숫자가 바뀝니다. **10 → 6**을 보여 줄 시간이 없다면, 잔여 12석·한 팀 최대 4명인 시간에 다른 손님으로 먼저 2명을 예약해 잔여 10석을 준비합니다. 한옥집 20시 매진 시연에는 그 시간에 예약이 없는 손님을 사용합니다.

다른 식당에서 매진 409를 준비할 때만 다음 명령으로 시간대를 채웁니다.

```bash
uv run python demo/make_full.py "동네백반"
```

출력된 날짜의 식당 상세에서 **매진 · 남은 0석**을 선택하고 예약하기를 누릅니다. 해당 시간에 예약한 적 없는 손님으로 1명을 선택하면 시연 로그에 **`409 SLOT_SOLD_OUT`**이 나옵니다. 한옥집 기본 시드의 첫날 20:00은 이미 만석이므로 새로 가입한 손님으로 바로 시연할 수 있습니다. 고객A·B는 그 시간에 이미 예약이 있어 중복 예약 409가 먼저 나옵니다.

## 5. API로 보여 주기 (`/docs`)

| 순서 | 하는 일 | 결과 |
| --- | --- | --- |
| 22 | 로그인 없이 `GET /api/v1/users/me/reservations` | **401** |
| 23 | `POST /api/v1/auth/login` → Authorize → `GET /users/me/reservations` | 200 |
| 24 | `POST /api/v1/auth/logout` → 같은 토큰으로 다시 `GET` | 204 → **401** (로그아웃한 토큰 차단) |
| 25 | `POST /api/v1/reservations`에 `party_size: 0` | **422** (입력 형식 오류) |
| 26 | `POST /api/v1/users`로 새 손님 가입 | 201 |
| 26-1 | 같은 이메일로 한 번 더 가입 (예: `customer.a@example.com`) | **400** `DUPLICATED_USER_ERROR` (중복 가입) |
| 26-2 | 비밀번호 `abcd` / 전화번호 `abc` / 이메일 `not-an-email` | **422** `VALIDATION_ERROR` (`errors`에 틀린 칸 이름) |
| 27 | 손님 토큰으로 `GET /api/v1/owner/restaurants` | **403** (운영자만) |
| 28 | `GET /api/v1/restaurants/999999` | **404** `RESTAURANT_NOT_FOUND` |

## 상태 코드 한눈에

| 코드 | 뜻 | 시연에서 내는 법 |
| --- | --- | --- |
| 200 | 성공 | 화면 열기 |
| 303 | 처리 뒤 다른 화면으로 (로그인·예약·취소 뒤) | 로그인, 예약하기, 취소 |
| 307 | 주소 옮김 | `127.0.0.1:8000` |
| 400 | 요청이 규칙에 안 맞음 (이미 가입한 이메일) | 3-2, 26-1 |
| 401 | 누군지 모름 (로그인 안 함·비밀번호 틀림·로그아웃한 토큰) | 2, 22, 24 |
| 403 | 누군지는 알지만 권한 없음 | 7, 8, 20, 27 |
| 404 | 없음 (또는 남의 것이라 숨김) | 9, 28 |
| 409 | 지금 상태와 부딪힘 (중복·인원 초과·마감·이미 취소) | 12, 13, 19, 마감(`make_full.py`) |
| 422 | 입력 형식이 틀림 | 3-1, 25, 26-2 (화면: 주소에 `?party_size=0`) |
| 500 | 서버 오류 | 시연에서는 나오지 않아야 함 |
